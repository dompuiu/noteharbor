# Triage Labels

tsk has no labels. The five canonical triage roles map onto tsk statuses, and
the two category roles map onto the thread.

## State roles

| Role | On the tsk board | Command |
| --- | --- | --- |
| `needs-triage` | status `open` | `tsk status T12 open` (the capture default) |
| `needs-info` | status `blocked`, waiting on the reporter | `tsk status T12 blocked --why "..." --needs "..."` |
| `ready-for-agent` | status `ready` | `tsk status T12 ready`; add `--assignee <profile>` when one is configured |
| `ready-for-human` | status `ready`, assigned to the user | `tsk status T12 ready` then `tsk edit T12 --assignee me` |
| `wontfix` | status `done`, then archived | `tsk status T12 done` then `tsk archive T12` |

A ticket has exactly one status, so conflicting triage states cannot coexist.
If a ticket looks like two roles at once, flag it and ask the maintainer.

`done` is normally the user's call. Setting it for `wontfix` is the one
exception, and it is always followed by `tsk archive`.

## Category roles

| Role | On the tsk board | Command |
| --- | --- | --- |
| `bug` | thread `bug` | `tsk add ... --thread bug` |
| `enhancement` | thread `enhancement` | `tsk add ... --thread enhancement` |

`tsk edit` cannot change a task's thread or scope. To recategorise, create the
task again on the right thread and trash the stray — say so before doing it.

## Writing triage notes

`tsk reply` only accepts text while a block or review is open. Put triage notes
on the ticket with `tsk edit T12 --append-notes "..."`, starting every entry
with the disclaimer the triage skill requires:

```
> *This was generated by AI during triage.*
```

## Reading the board as triage buckets

| Bucket | Query |
| --- | --- |
| Never triaged | `tsk list --open --json` |
| Needs evaluation | `tsk list --open --json`, thread `bug`/`enhancement` |
| Waiting on the reporter | blocked rows whose `block.on` is `you` |
| Ready to pick up | `tsk list --ready --json` |
| Won't fix | `tsk list --archived --json` |
